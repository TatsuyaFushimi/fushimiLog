AIは万能ではない — 知っておくべきリスク リスク理解

ClaudeCodeは非常に高性能だが、指示した内容を忠実に実行するがゆえに危険になることがある。AIを安全に使うにはまず「何が怖いか」を知ることが出発点。

⚠️ 巻き戻せない操作がある

ファイルの削除・データベース更新・デプロイ・課金処理など、一度実行したら取り消せない操作がある。「やってしまってから気づく」では手遅れ。

⚠️ 知らないコマンドを許可してはいけない

AIが「このコマンドを実行していいですか？」と聞いてきたとき、内容を理解せずに「OK」を押してはいけない。何をするコマンドか確認してから許可すること。

⚠️ プロンプトインジェクションのリスク

悪意のあるテキストが含まれたファイルをAIに読み込ませると、そのテキストの指示に従って意図しない動作をする可能性がある。外部ファイルの取り扱いに注意。

⚠️ 機密情報の漏洩リスク

APIキー・パスワード・個人情報をチャット欄に直接貼り付けると、ログや会話履歴に残る。機密情報はファイル経由で渡すのが原則。

非エンジニアでも実践可能 — 7つのセキュリティ対策 設定
  • 1
    機密ファイル（.env）を作業フォルダの外に隔離する
    APIキーやパスワードが入った.envファイルは、ClaudeCodeが作業するフォルダの外に移動。誤って読み込ませるリスクをゼロにする。
  • 2
    .claudeignore で読み込み禁止エリアを設定する
    ClaudeCodeに見せたくないファイル・フォルダを.claudeignoreに記載。.env・パスワードファイル・個人情報フォルダなどを指定する。
  • 3
    settings.json で実行できるコマンドを制限する
    allowリスト（許可）・denyリスト（禁止）を設定。特にBash(rm -rf /)などの危険なコマンドは必ずdenyに入れる。
  • 4
    CLAUDE.mdにセキュリティルールを明記する
    「元ファイルを削除しない」「外部に送信しない」などのルールをCLAUDE.mdに書く。毎セッション読み込まれるので、常にルールが守られる。
  • 5
    AI学習設定をオフにする
    Anthropicの設定画面で、入力データが学習に使われないよう設定を確認・変更する。Pro/Teamプランではデフォルトでオフだが、必ず確認すること。
  • 6
    タスクが終わったら会話をリセットする
    1つのタスクが完了したら新しい会話を開始する。長い会話はトークン消費が増えるだけでなく、情報の混在リスクも高まる。
  • 7
    知らないコマンドは許可しない
    AIが何か実行しようとしたとき、内容を理解してから許可する。「よくわからないけどOK」は厳禁。必要なら「このコマンドは何をするの？」とAIに聞く。
settings.json の設定例 コード例

プロジェクトの.claude/settings.jsonに以下を記載することで、実行できるコマンドを制限できる。

{ "permissions": { "allow": [ "Bash(pdftotext *)", "Bash(find * -name *.pdf)", "Bash(mkdir *)", "Bash(mv *)" ], "deny": [ "Bash(rm -rf /)", "Bash(curl *)", "Bash(wget *)", "Bash(ssh *)" ] } }
⚠️ bypassPermissionsモードを使う場合は、denyリストで危険なコマンドを必ずブロックすること。設定なしの全許可は危険。

# 機密ファイル .env .env.local secrets/ credentials/ # 個人情報フォルダ personal/ private/
「Human-in-the-Loop」の考え方 実践

ClaudeCodeは「AIが全部やる」ではなく、人間が要所でチェックしながら進める設計になっている。これが「AIは万能ではない」という前提の本質。

AIに任せていいこと人間が必ず確認すること
ファイルの読み込み・要約外部へのデータ送信
ドキュメントの作成・編集ファイルの削除・移動
コードの生成・レビューデプロイ・公開処理
反復的な定型作業課金・決済が発生する操作
情報の整理・分類パスワード・APIキーを含む操作
💡 「巻き戻せる操作」はAIに任せ、「巻き戻せない操作」は人間が最終確認するのが鉄則。
