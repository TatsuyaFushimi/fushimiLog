Claude Code 活用ガイド ／ AI関連 #19

サブエージェントで
AI精度を劇的に上げる

役割を分担した専門AIチームを作ることで、コーディングミスの削減・提案精度の向上・作業の可視化ができる。このガイドはPJを始めたその日に設定することを強く推奨する。

なぜ最初に設定すべきか

🎯
精度が上がる 実装・チェック・調査を別々のAIが担当するため、見落としが激減する
👁️
作業が見える 誰が何をしているかカラーコードで一目でわかる。ブラックボックスにならない
📂
知識が蓄積する 作業のたびに知見が自動でドキュメントに反映される。属人化しない
PJ作成後すぐに設定しよう。 途中から入れると、過去の知見が蓄積されない・既存ルールとの整合性調整が必要になる。最初の5分で設定するのが一番コスパが良い。

1

チームを設計する（チャット前の準備）

Claude Code を開く前に、作りたいチームを頭の中で整理しておこう。メモ帳や紙に書いておくだけでOK。チャット中に聞かれたことに答えるだけで全部作ってくれる。

🗒️ チャット前に決めておくこと

秘書役（メインAI）の名前と役割 例：「秘書丸」 — 要望を受けてメンバーに振り分ける司令塔
各メンバーの名前・役割・色 例：「コーディー / 実装担当 / 🟠」「レビュアン / 最終チェック / 🩷」
やらせたいルール（あれば） 例：「git pushは私が言うまでしない」「作業前に必ず確認する」など

最小構成の参考（迷ったらここから）

📂.claude/ 管理役強く推奨

作業前に既存のルール・スキルを確認し、作業後に知見を記録する。これがいると知識がどんどん蓄積される。

💻実装役強く推奨

コーディングをするなら必須。バグゼロ・指示範囲を守ることに特化させると品質が上がる。

✅最終チェック役推奨

ユーザーへ返す前のGO/NG判定。これがいるだけで出力の品質が安定する。

🔎調査・提案役任意

技術選定や複数案の比較が必要なとき。なくても動くが、迷う場面が多いなら入れると良い。

2

チャットで一緒に作る

Claude Code を開いて、以下の順番でメッセージを送るだけ。ファイルを手動で作る必要は一切ない。全部 Claude が作ってくれる。

会話を進めるペースは自由。 一度に全員分送っても、1人ずつ確認しながら進めても OK。わからないことは「これってどういう意味？」と聞けばすぐ教えてくれる。
あなた 必ず送る ①
サブエージェントチームを一緒に作りたい。私の専属AIチームを設定してほしい。
Claude の返し（例）
「了解です！まず秘書役（メインAI）から始めましょう。秘書役の名前と、どんな役割にするか教えてください」
次に秘書役を伝える
あなた 必ず送る ②
秘書役の名前は「〇〇」。役割はユーザーの要望を受けてメンバーに振り分ける司令塔。キャラクターは〔どんな人物か〕。
Claude の返し（例）
「〇〇を設定しました！次にサブエージェントを作りましょう。一人ずつ教えてください。名前・役割・色（絵文字）・キャラクターをざっくり教えてもらえれば作ります」
メンバーを1人ずつ伝える
あなた 必ず送る ③（全員分）
「△△」という「〔役割〕」担当を作って。〔絵文字〕色。キャラクターは〔性格・外見など〕。
Claude の返し（例）
「△△を作りました！他にもメンバーはいますか？」
🔁 メンバーの人数分これを繰り返す。全員終わったら「これで全員です」と送る。
次にルールを伝える
あなた 必ず送る ④
こんなルールを設定して： ・実装前に必ず私に確認する ・git push は私が「push して」と言うまでしない ・作業開始時に、誰が何をするか宣言する ・〔他に守らせたいことがあれば追記〕
Claude の返し（例）
「workflow.md にルールを追加しました。CLAUDE.md（プロジェクトの憲法）も作りましょうか？」
最後にプロジェクト概要を伝える
あなた 推奨 ⑤
CLAUDE.md も作って。プロジェクトの概要は「〔何を作るか・何のためか〕」。チームメンバーとルールはさっき決めた内容でよろしく。
Claude の返し（例）
「CLAUDE.md を作りました！エージェントファイル・ルールファイル・CLAUDE.md の設定が完了です。テストしてみましょうか？」
途中で詰まったら： 「もう一度説明して」「これってどういうこと？」と気軽に聞いてOK。Claude が案内してくれる。
3

動作確認

設定が完了したら、一言送ってみよう。全員がキャラクターに沿って返事をしてきたら成功。

あなた これを送る
メンバーを紹介してください。
🎉
各メンバーが自己紹介してきたら完成！
全員の名前・役割・キャラクターが正しく紹介されたら、チームの設定は完了です。
ボーナス：挨拶ルールも追加してみよう。 「workflow.md に、私が "おはよう" や "ただいま" と言ったときに全員が挨拶するルールを追加して」と送ると、毎日の挨拶もできるようになる。
4

キャラクターを育てる（任意・継続的に）

キャラクターを設定すると、挨拶・作業宣言・フィードバックに個性が出て、AIとの作業が楽しくなる。長く使うほど育っていく感覚がある。

キャラクター設定の考え方

決めること例
外見・年齢・性別ムキムキおじさん、眼鏡の青年、小柄な少女、姐さん など
口癖・喋り方ぼそぼそ、ウズウズ、熱血、自分の言葉を添削する など
仕事への姿勢死ぬ気でやる、壊すことが生きがい、GO出す瞬間が好き など
ギャップ・弱点几帳面に見えるが部屋が汚い、知識あるが主張しない など
カラー🟡🔵🟠💚🩷 など絵文字で識別
FBを返してキャラを育てよう。 「もっとこういう喋り方にして」とフィードバックするたびにキャラが洗練されていく。最初は荒削りでOK。使い続けながら理想のチームに育てていこう。

エージェントファイル（最小構成）

~/.claude/agents/your-agent.mdmarkdown
---
name: your-agent-name
description: Use when [この人を呼ぶタイミングを英語で].
---

あなたは[名前]、[役割]担当。

## カラー識別
すべての回答の冒頭に必ず `[絵文字] [名前]：` を付ける。

## キャラクター
[性格・口調・外見・口癖など]

## 役割
- [やること1]
- [やること2]

## ルール
- [守ること]
- [禁止事項]

## 出力形式
[どういう形式で結果を返すか]

CLAUDE.md（最小構成）

.claude/CLAUDE.mdmarkdown
# プロジェクト名

## このプロジェクトでの役割
[秘書役AIが何をするかを書く]

## チームメンバー一覧
| メンバー | 色 | 役割 | キャラクター |
|---|---|---|---|
| [秘書役名] | なし | 司令塔 | [説明] |
| [名前] | [絵文字] | [役割] | [説明] |

## カラー識別
[秘書役]はすべての回答に `[名前]：` を付ける。
サブエージェントは各自の絵文字+名前を付ける。

## 禁止事項
- 確認なしで実装・ファイル編集を開始すること
- 指示なしでの git push
- 指示されていないリファクタリング・機能追加

## デプロイ・実装手順
→ `.claude/rules/workflow.md` に詳細あり。

Tips

  • ✓
    グローバル（~/.claude/agents/）に入れると全PJで使える
    コーディー・レビュアンなど汎用的なエージェントはグローバルに。PJ固有のものは.claude/agents/に
  • ✓
    rules/に書いたことは常に有効
    「絶対に忘れてはいけないこと」はrules/へ。skillsは呼ばれたときだけ発動
  • ✓
    knowhow.mdにハマりポイントを蓄積する
    .claude/管理役に事後記録させると、同じ失敗を繰り返さなくなる
  • ✓
    キャラはFBで育てる
    「もっとぼそぼそ喋って」「おじいちゃんらしく」などFBするとキャラが洗練される
  • ✓
    挨拶ルールを入れると毎日が楽しくなる
    「おはよう」と言うとメンバー全員から挨拶が来る。モチベーションが上がる
